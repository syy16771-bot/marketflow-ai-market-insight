# 04｜评测与最终验收

## 评测目标

评测关注四件事：结构是否完整、证据是否存在、数字是否一致、建议是否可追溯。文字是否“像专家报告”不是唯一成功标准。

## 固定测试集

| Demo | 核心验证方向 |
| --- | --- |
| Portable Blender | 复杂食材处理、清洗、便携体验 |
| Pet Water Fountain | 清洁维护、滤芯成本、噪音 |
| Ergonomic Seat Cushion | 支撑稳定性、尺寸适配、舒适度 |

## 自动验证指标

| 指标 | 定义 | 当前结果 |
| --- | --- | ---: |
| Pipeline 成功率 | 完整链路成功的 Demo 比例 | 100% |
| Schema 成功率 | 输出通过结构校验的比例 | 100% |
| Evidence ID 有效率 | 引用 ID 可在当前数据中找到 | 100% |
| 确定性数据一致率 | 价格、数量和频次未被改写 | 100% |
| 建议关联率 | 建议关联有效痛点或机会 | 100% |
| 无依据结论数 | Validation 标记的 unsupported claims | 0 |

## 端到端验收路径

每个 Demo 都执行：

```text
输入
  → analysis
  → Mock LLM
  → Schema Validation
  → Evidence Validation
  → Consistency Check
  → final_report
  → 结果页面
  → 可信度页面
```

最终结果：**3/3 通过，端到端通过率 100%**。

## 页面验收项

- 分析工作台能够选择并运行三个 Demo；
- 商品分析能够展示定位、用户、场景、卖点和信息缺口；
- 竞品矩阵显示价格、评分、评论数、功能、Evidence ID 和 Data Fact；
- 痛点显示频次、严重程度、证据状态和评论依据；
- 建议关联有效痛点或差异机会；
- Data Fact、Calculated、AI Inference、Recommendation 均正确展示；
- 可信度页面显示数据来源、Validation 状态和限制。

## 成绩解释

当前成绩来自固定 Synthetic 数据和 Mock 输出，证明公开 Demo 的结构、证据链、验证门禁和页面链路可以稳定复现。

该成绩不等于真实模型准确率，也不代表真实跨境市场效果。真实 LLM 需要另外评估：

- 多次运行的核心结论一致性；
- 人工标注痛点的召回和精度；
- 建议具体性与可执行性；
- 过度推断率；
- 不同商品类别下的泛化能力。

## 人工评测建议

使用 1–5 分评价商品定位清晰度、竞品差异准确性、痛点合理性、证据充分性、建议可执行性和优先级合理性，并保存失败案例用于下一轮迭代。

# 03｜AI 治理与幻觉控制

## 治理目标

MarketFlow AI 不假设 LLM 会始终遵守 Prompt。产品同时使用生成前约束和生成后验证，降低无依据事实进入决策报告的风险。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 编造竞品或评论 | 只允许引用当前数据集中的 Evidence ID |
| 算错价格、数量或频次 | 数字由确定性分析层生成，输出后再次比对 |
| 输出字段缺失或格式漂移 | 使用独立 JSON Schema 校验 |
| 痛点没有用户证据 | 痛点必须关联有效评论 ID |
| 建议与发现脱节 | 建议必须关联痛点或差异机会 |
| 数据不足仍强行结论 | 使用 `insufficient_evidence` 和置信度降级 |
| 小样本被包装成市场趋势 | 明确显示 Synthetic 数据来源和限制 |

## 四类来源标签

### Data Fact

直接来自本地样例的原始字段，不由模型生成。

### Calculated

程序基于样例确定性计算的指标，置信度固定为 1。

### AI Inference

模型基于允许证据形成的解释性结论。它必须包含证据 ID 和保守置信度，不能被展示为事实。

### Recommendation

基于已验证痛点或机会形成的行动建议。它表达下一步选择，不表达已经发生的商业结果。

## Prompt 边界

Prompt 明确要求：

- 不使用模型记忆补充市场、品牌或平台事实；
- 不生成输入中不存在的竞品和评论；
- 不计算价格、评论数量、平均评分或频次；
- 不承诺无数据支持的销量或转化效果；
- 输出严格 JSON，不附加自由文本解释。

## 证据不足协议

证据不足时，系统不会通过语言包装掩盖不确定性：

- 无法形成完整阶段结果时返回 `insufficient_evidence`；
- 单条证据支持的痛点标记为 `limited`；
- 无证据的结论不生成；
- 商品描述缺失项进入信息缺口；
- 验证失败时不生成最终报告。

## 可信度的产品表达

可信度不是只显示一个百分比。页面同时展示来源标签、Evidence ID、数据集版本、Validation 状态和限制，使用户能理解结论的形成过程。

## 当前治理边界

Mock 验收只能证明 Pipeline、约束和展示机制工作正常，不能证明真实 LLM 在开放输入下的业务质量。真实模型需要单独执行稳定性、人工质量和失败案例评测。

# 05｜面试介绍与常见问答

## 30 秒介绍

MarketFlow AI 是一个跨境电商市场洞察助手，把商品资料、竞品样例和用户评论转化为商品定位、竞品差异、用户痛点和优化建议。项目的重点不是让 AI 自由写报告，而是建立可信决策链路：数字由程序计算，AI 只处理语义洞察；每条结论都带 Evidence ID、置信度和来源类型；最终结果还必须通过 Schema、Evidence 和 Consistency Validation。三个公开 Demo 已完成端到端验收，通过率 100%。

## 3 分钟介绍

我做这个项目，是因为跨境新品规划和商品优化经常面临同一个问题：商品资料、竞品参数和用户评论分散，人工整理耗时，而通用 AI 总结又容易混淆事实、计算结果和模型判断。

所以我没有把目标定义成“生成一份市场报告”，而是聚焦四个业务问题：商品应该如何定位、与竞品有什么差异、用户真正遇到了什么问题、下一步应该优先优化什么。

产品设计上，我先把确定性计算和 AI 推断分开。价格区间、评论数量、平均评分和频次由程序计算；AI 负责商品定位、痛点解释、差异机会和策略建议。这样既使用了语言模型的语义理解能力，也避免让模型处理不擅长且容易验证的数字任务。

第二个设计是证据链。每条关键洞察都有 Evidence ID、置信度和来源类型。痛点必须关联当前 Demo 中存在的评论，建议必须关联已经验证的痛点或竞品机会。用户可以从一条建议一直追溯到原始数据。

第三个设计是独立 Validation。模型输出不会直接进入页面，而是依次检查结构、Evidence ID 和确定性数据一致性。任一关键检查失败，系统停止生成最终报告。Prompt 负责降低错误概率，Validation 负责阻止错误进入产品。

当前公开版使用三个 Synthetic Demo 和 Mock 输出，端到端验收为 3/3。这个成绩证明的是 Pipeline、证据链、验证和页面展示稳定，不代表真实模型准确率。真实 LLM 质量需要使用独立数据集和人工评分另行评测。

这个项目体现的核心产品能力是：从业务决策问题定义范围，合理划分 AI 与程序的职责，并将可信度和评测机制设计进产品，而不是把它们作为上线后的补充。

## 常见面试问题

### 1. 这个产品解决什么问题？

它解决新品规划和商品优化阶段信息分散、结论缺少依据、建议难以落地的问题，把商品、竞品和评论整理成统一且可追溯的决策报告。

### 2. 为什么需要 LLM？

LLM 用于商品定位、评论语义、差异机会和策略建议等需要理解上下文的任务。价格、数量和频次等确定性内容不使用 LLM。

### 3. 如何控制 AI 幻觉？

通过限定输入、禁止模型计算关键数字、要求 Evidence ID、使用 JSON Schema，并在输出后进行证据和一致性检查。错误结果不能进入最终报告。

### 4. 为什么 Prompt 之外还需要 Validation？

Prompt 只能降低错误概率，Validation 才能提供可复现的确定性门禁。两者分别解决“尽量生成正确”和“错误不能被展示”。

### 5. 为什么使用 Synthetic 数据？

固定样例便于控制变量、设计预期结论、复现失败场景，并避免把无法验证的商业数据包装成真实洞察。项目会明确展示数据来源和限制。

### 6. 100% 通过率代表真实模型准确率吗？

不代表。它只代表三个固定 Demo 在 Mock 模式下的 Pipeline、Schema、证据、一致性和页面验收全部通过。真实模型效果不计入该成绩。

### 7. 如何判断建议可靠？

建议必须关联有效痛点或差异机会，同时带 Evidence ID、置信度、优先级、实施难度和风险提示。无关联建议会被验证层拦截。

### 8. 最大的产品取舍是什么？

选择“小而可信”，而不是加入实时搜索、市场规模和收入预测。当前优先验证洞察链路和可信度控制，而不是扩大功能数量。

### 9. 下一步会如何迭代？

优先增加受控数据上传、人工评分基准和真实模型稳定性测试，再考虑扩展数据源。先验证质量，再扩展覆盖范围。

### 10. 这个项目如何体现 AI 产品能力？

它展示了业务问题定义、MVP 取舍、AI 与确定性逻辑分工、结构化输出、风险治理、评测指标和端到端验收，而不仅是模型调用。

## 五分钟演示顺序

1. 用一句话说明业务问题和产品定位。
2. 在分析工作台选择一个 Demo 并运行。
3. 展示竞品矩阵和一个带评论 Evidence ID 的痛点。
4. 展示建议如何关联痛点或差异机会。
5. 打开可信度页面解释四类来源标签与 Validation。

演示时应主动声明 Synthetic 数据和 Mock 验收边界，不把稳定 Demo 表述为真实模型效果。
